# 本文から再注釈した日本語データの暫定評価

Codexが本文からタグを付け直した314件を、既存のGiNZA＋日本語ルールで評価した。
検出処理と辞書は変更していない。131文書の判断事項が未確認なので、これは
人手確認前の暫定評価であり、最終的な精度値ではない。
[レビュー・再測定の手順](../datasets/ai4privacy-reannotated.md)を参照。

## 入力

- 元資料9,990件を本文から選別。採用314件、除外9,676件。
- train 282件・1,669タグ、validation 32件・168タグ。元のsplitを保持。
- 全1,837タグのうち、アプリ対応1,288件、拡張分類549件。
- 出力revision 0 / `codex_draft`。人が確認した文書は0件。
- 検証用JSONL SHA-256: `ece1daec6a1032d617d10c9c13b3979d052c45958dc6730734704c08071d4741`。
- 学習用JSONL SHA-256: `411c3e3024439229bf871133729e33e44acc6f6e23fb094c55ae5c3ab3395db0`。
- 原文の変更なし、タグからの辞書登録なし、アプリにない分類も保持。
- 出典: ai4privacy/pii-masking-mini-10k、CC BY 4.0、© 2026 Ai Suisse SA / ai4privacy。

## 精度

| 指標 | validation（主結果） | train（参考） |

元配布タグを使った評価のvalidation 33件・F1 17.95%とは、採用文書・タグ・
住所の範囲などが異なる。数値の差を検出器の改善として扱わない。
再注釈後も未検出が多く、データの不一致だけで低い検出率が説明できる結果ではない。
人が確認した版で、分類・文字範囲の違いとアプリの検出不足を再評価する。

## 処理時間

Python 3.11.9 / GiNZA 5.2.0。同じ端末でsplitごとに3回、別プロセスで順番に測定。
各回10文書を追加でウォームアップし、その後全対象を処理した。
以下は各指標の3回の中央値。モデル読込、データ読込、manifest照合、採点、通信、
人の確認時間は検出時間に含まない。別アプリ・OSの負荷は完全には固定していない。

| 指標 | validation 32件 | train 282件 |
| --- | ---: | ---: |
| 合計 | 1,156.551 ms | 11,815.744 ms |
| 1文書の平均 | 36.142 ms | 41.900 ms |
| 1文書の中央値 | 28.080 ms | 33.825 ms |
| p95 | 100.535 ms | 87.812 ms |

validationの合計は1,238.958 / 1,152.274 / 1,156.551 ms、
trainは11,844.546 / 11,641.305 / 11,815.744 ms。
3回とも同じ精度になった。生の記録は `build/reannotation-validation-1.json` など、
集約は `build/reannotation-summary.json`。

今回の変更は評価データとレビュー・入出力の処理。検出器本体は変更していない。
以前の33件・300件とは入力も件数も異なるので、以前の合計時間との差から
高速化・低速化の率は算出しない。今後検出処理を変更するときは、この同一revisionを
入力にして、変更前後を交互に測定する。
