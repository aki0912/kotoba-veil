# 本文から作り直した日本語PIIデータ

Codexが本文を読んで再注釈したローカル評価データ。元の正解タグ、マスク文、
言語ラベル、現在の検出器の予測を正解生成には使わない。
原文は変更せず、配布元のIDとtrain / validationだけを追跡情報に使う。

初版は **314文書・1,837タグ**。train 282件、validation 32件。
アプリに対応するタグ1,288件と、拡張分類549件を保存した。
判断が曖昧な **131文書** は理由を付けてレビュー対象にした。
これはCodex作成の暫定版であり、人間が全件を確認した正解ではない。
[注釈方針](ai4privacy-reannotation-policy.md)と確認画面で最終判断を行う。

## 作成と選別

原本9,990件をSHA-256で照合し、`source_text` と `uid` だけを抽出した。
splitは読み込んだファイル名から保持する。仮名を含む326件をCodexが読み、
日本語が値として含まれるだけの英語13件を除いた。さらに仮名なし・漢字あり・
ハングルなしの338件を中国語表現と本文で選別し、日本語の項目表1件を採用した。
残りは日本語の仮名・漢字による本文がない、またはハングル本文として除いた。
文字種は候補選別の手段であり、元データの言語ラベルを信用して絞ったものではない。

採用した314件はすべてCodexによる個別の再注釈がある。タグのない文書も残す。
難しい文章を高スコアのために除外しない。元データの金額を年齢、注文番号を免許番号、
口座番号をカード番号とするような分類は、本文に基づいて付け直した。
曖昧な省略日付、連続する人名、金額か番号か判別できない数字列などはレビューへ回した。

選別で除いた9,676件も確認用には保存する。評価用JSONLには日本語として採用した文書だけを出す。
「除外した文書」で採否を修正し、タグを追加して確認済みにすれば復帰できる。
検出器のルール・学習モデル・辞書への正解の埋め込みは行っていない。

## レビュー画面

プロジェクトのルートで起動する。

```bash
.venv/bin/python -m benchmarks.review_reannotations --port 8012
```

[レビュー画面](http://127.0.0.1:8012)で次の順に確認する。

1. 「タグの付け方と評価範囲」を読み、方針の確認を保存する。
2. 初期表示の「要確認・未確認」から本文と確認理由を読む。
3. タグ一覧の種類を変更・削除できる。追加は本文を選択して「タグを追加」。
   範囲を直す場合は該当タグを削除し、正しい文字を選び直す。
4. 必要なら判断メモを書き、「本文・タグ・上の確認事項を確認した」をチェックして保存する。
5. 要確認が0件になったら「要確認のレビューを完了して書き出す」。

要確認以外も「採用した文書」「すべての原文」から修正可能。
検索は本文・ID・確認理由を対象にする。本文自体は編集しない。
「保存前の状態に戻す」は未保存のタグ変更を戻す。
保存された変更は `review.json` の `history` に変更前後を残す。
同じ版を複数の画面で変更した場合は後の保存を拒否する。
編集後に確認済みへチェックしていない文書は、もともと確認事項がなかった場合も要確認へ戻る。

出力状態は `codex_draft` と `review_complete` を区別する。
後者も「要確認のレビューが完了した」という意味で、全件を人が確認した保証ではない。
人が確認した文書数・全採用文書の人手確認の有無もmanifestへ記録する。
完了後に編集すれば再び暫定版となり、再出力が必要になる。

## アプリで測定する

「現在の版を書き出す」で、未確認項目を残した暫定版も生成できる。
出力先は `data/annotation-review/ai4privacy-ja/exports/revision-番号-状態/`。
ファイルは版ごとに保持するので、古い測定の入力は後の編集で変わらない。
ダウンロードして使う場合はJSONLと `manifest.json` を同じフォルダに置く。

初版の暫定評価は次のコマンド。確認前のため `--allow-draft` を明示する。

```bash
.venv/bin/python -m benchmarks.run \
  --dataset data/annotation-review/ai4privacy-ja/exports/revision-0-codex_draft/ja-validation.jsonl \
  --allow-draft --warmup 10 \
  --output build/reannotation-validation.json
```

学習用の参考評価には同じフォルダの `ja-train.jsonl` を指定する。
学習用と検証用は混ぜない。ここでモデルの学習は行わない。
確認完了後は書き出された `revision-番号-review_complete` のファイルを指定し、
`--allow-draft` を外して実行できる。

`entities` はアプリに対応するタグ、`source_entities` は拡張分類を含む再注釈の全タグ。
後者は元配布タグのコピーではない。AGE、SEX、GENDER、PASSPORT、TAX_ID、SOCIAL_ID、
ORDER_ID、IDENTIFIER、PAYMENT_IDは分類を失わずに保持し、文字単位のマスク率で評価する。
完全一致の指標にはアプリ非対応分類を含めない。レポートのmanifestにも件数を残す。

測定前に出力のチェックサムと状態を確認する。レポートには使用した入力SHA-256、
検出器SHA-256、注釈状態、確認状況、処理時間を残す。現在の検出器の改善とは区別して読む。

## 保存と再構成

作業本体は `data/annotation-review/ai4privacy-ja/`。次をまとめて保管する。

- `texts-only.jsonl`：本文と追跡情報だけの全件スナップショット。
- `annotations/batch-*.json`：Codexが本文を読んで書いた327件の採否・タグ・確認事項。
- `source.manifest.json`：配布元とスナップショットのSHA-256。
- `codex-draft.json`：選別結果を含む初期レビュー用データ。
- `review.json`：人の編集・確認状態・履歴。初回の画面起動で作成する。
- `exports/`：版ごとのアプリ対応データとmanifest。

```bash
.venv/bin/python -m benchmarks.reannotation --complete
```

このコマンドは保存済みのCodex注釈を検証して初版を再構成する。
新しい本文に対するAIの自動タグ付けコマンドではない。
原本がキャッシュされていない場合は、先に[配布元データの取得手順](ai4privacy-mini.md)を実行する。
元の注釈ファイルは再構成の前提であり、データ本体はGitへ追加していない。

原本との本文一致、候補の処理漏れ、未知の漢字のみの候補、重複ID、文字範囲の重なり・不一致を拒否する。
`review.json` はこのコマンドで上書きしない。人の編集後にCodex初版が変更された場合も、
画面起動時に検出して保存済みの人の確認を保護する。
